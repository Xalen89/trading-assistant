# Strategies, attached indicators, confluence gates, and quantitative workbench

**Read-only source audit** · capability ID: `strategies` · project: `/home/ubuntu/stratdesk`

## Scope and evidence boundary

This guide describes the controls and behavior present in source, not a redesigned feature promise. The app is an owner-only, paper-only Expo RN/web product. This audit did not use a browser, read/write owner database or API data, execute brokerage actions, upload source files, or access attached images. The named source and associated unit-test files were read; fixture tests are not device or integration proof. No market data, simulated fixtures, or test outputs establish profitability, predictive ability, or a statistical edge. The common workbench UI/API service path is not diagnosed here.

**Operational output is not validation.** “Ready” below means only that a source calculation could emit a result under its own rules. It does not mean a trader has a statistically validated strategy, an executable fill, permission to submit an order, or a broker route. The pure quant modules do not fetch data themselves; the workbench's Run action asks its model service for a response. This audit did not verify service/device availability.

## Automatic setup evidence on chart

Applying supported source styles lets the setup engine evaluate completed supplied OHLC bars. The engine returns candidate(s), per-step status/evidence, zones/levels, optional entry/stop/target references, and messages. It also can provide historical scenario context and a descriptive historical estimate; those outputs are explicitly not forecasts/probabilities.

- **Core Sequence**: hourly direction context → confirmed prior-swing sweep/rejection → directional body at least prior ATR → structural close-through/MSS → a regular three-bar FVG or last-opposite order-block body/CE alternative → a later closed-bar CE retest. A zone alone is not an entry.
- **Sweep + FVG / Silver Bullet** requires the FVG path, but session timing remains manual/source-connected and is not confirmed from candles.
- **Order Block Retest** requires the last-opposite candle body/CE path.
- **STDV Manipulation-Range Targets** projects negative Fibonacci ratios **−2/−2.5/−4** from displacement and swept extremes. It is a target reference, not statistical standard deviation and not a standalone entry model.
- **STDV · VWAP Re-entry** and the indicator families use separate numerical paths described below. Unsupported/manual discretionary source definitions remain unknown rather than passed.

**Data requirements and no-signal meaning:** the engine discards still-forming/future candles and uses closed bars; fewer than eight execution bars produces a “too few” message, and at least three are needed before sequence candidates are even formed. Six completed hourly bars are needed to infer directional hourly context. Unknown or neutral context does not become a pass. Automatic reference execution readiness is limited to 1m–15m; at 1h and slower the candidates are forced not-ready because hourly context is no longer higher than execution. The engine analyzes at most the first three distinct selected rulebooks. More than three yields a truncation message. If the selected definition has no supported detector, no candidate or strategy-conditioned history is invented. “Waiting” is a determinate missing/not-yet event, “failed” is an opposing/invalid event, and “unknown” is unavailable evidence; none should be read as a passed condition.

When data and rules do not qualify, the actual result can be no candidate, partial steps, unknown/waiting/failed steps, no entry reference, or `ready: false`. Follow the evidence/message and obtain the missing valid closed history/context; do not infer a trade from an overlay or a partial pattern. A displayed historical estimate is not a calibrated probability: the engine keeps `probability: null`, excludes trading costs/microstructure, and withholds the empirical rate unless at least 100 resolved non-overlapping historical cases exist.

## Strategy-attached chart indicators

The strategy visibility helper attaches only layers declared by currently visible, non-archived strategies. The chart receives line series (up to 48 fragments per line), not strategy rules being evaluated. Hiding a style removes its layers; showing two styles combines their layers.

| Strategy declaration | Actual chart layer(s) | Formula / practical interpretation and limits |
|---|---|---|
| Trend Following | EMA20, EMA50, 2×ATR14 guide | EMA uses an initial period SMA seed then α=2/(n+1). ATR14 uses Wilder smoothing. The guide is close − 2×ATR; it is not a ratcheted or trade-specific trailing stop. |
| Mean Reversion | Bollinger20 mid/upper/lower ±2σ, RSI14 | BB uses 20-close SMA and population standard deviation; RSI14 uses Wilder-style smoothing. |
| SMA Crossover | SMA20 and SMA50 | Simple close averages. |
| MACD Momentum | MACD12/26/9, signal and histogram | Price EMAs are SMA-seeded; initial warm-up/convergence is not guaranteed by minimum bars. |
| Donchian Breakout | Prior Donchian20 high/low | Uses the prior 20 bars and excludes current bar. |
| Breakout Momentum | Prior 10-bar high/low | The range lines are based on the ten bars before the current bar. The source also asks for volume/catalyst/execution checks not supplied by these lines. |
| STDV · VWAP Re-entry | OHLCV rolling VWAP20 and upper/lower VWAP±2.5σ | Typical price weighted by actual volume; 20 completed-bar rolling window; volume-weighted population σ. It is a bar proxy, not exchange trade/tick VWAP. Only a source label matching Coinbase Exchange is treated as known single-venue volume; other volume semantics are unverified. Missing/negative volume or all-zero windows make affected curves unavailable, not imputed. |
| Custom personal rules | Only explicit supported indicator declarations are recognized: EMA20/50, SMA20/50, RSI14, BB20, Donchian20, MACD12/26/9 | A factor name/prose without a recognized explicit period cannot create a layer. No arbitrary indicator period is inferred. |

Warm-up is real: EMA20/SMA20/BB20 require 20 closes; EMA50/SMA50 require 50; source Trend Following's five-bar EMA slope needs 55; RSI/ATR need prior history; Donchian needs 20 prior bars; MACD needs 12/26/9 seeding and a signal line. Missing warm-up observations are absent, not zero. RVOL20 uses the current completed bar's volume against the preceding 20 positive volumes; it is not time-of-day normalized. Provider/broker volume units are generally not established. Consequently a plotted indicator does not prove the strategy's full source-specific filter or executable signal.

## Sourced confluence gate

### What it answers

The gate answers: **“For this exact strategy version and this concrete long/short setup candidate, did the explicitly selected native closed-OHLC trigger occur, and did enough of my weighted native conditions pass on a fresh prior-closed bar to meet my threshold?”** It does not estimate a win probability and does not submit/queue/automate an order.

### Tap-by-tap setup and output

1. Tap a saved strategy, then **Configure confluence gate** (or **Review approved confluence gate**). The page queries setup analysis for the current workspace market and timeframe, using the selected strategy and exact current strategy version.
2. Wait for analysis. If there is no same-version candidate or no supported native trigger/condition set, the editor explains that closed-bar analysis or a candidate is missing; the gate cannot convert manual/session/HTF/news/quote/free-text items into sourced conditions.
3. If multiple candidates appear, tap one concrete candidate. Long and short evidence is never silently merged.
4. Under **1 · Explicit trigger**, tap one actual allow-listed native step. The draft initially prefers a family-specific trigger (often retest/re-entry/crossover), but the reviewer can choose another available step.
5. Under **2 · Weighted conditions**, enable/exclude each other native step, enter point weights, and use **Normalize weights** when necessary. A newly exposed condition gets zero points until adjusted/normalized. Enabled weights must total 100 for a valid contract; the engine does not silently normalize. The UI reports enabled total.
6. Under **3 · Gate and approval**, set the inclusive deterministic threshold (0–100), inspect validation errors, check the acknowledgement that you reviewed the trigger/conditions/weights and understand it is paper-review eligibility, then tap **Approve confluence configuration**. Any edit returns it to draft and requires another review.
7. The saved config is bound to the current strategy ID/version, chosen side, exact trigger/condition step IDs, and the selected closed-OHLC timeframe. The strategy sheet attempts canonical cloud save, retains the edit locally if that save fails, and tells you to refresh a paper proposal before strategy mode.

### What the gate actually computes

- Only candidate-local, allow-listed closed-OHLC setup steps can be used. Examples include sequence steps such as sweep/displacement/MSS/FVG/OB/retest, VWAP-standard-deviation steps, supported trend/breakout/mean-reversion/SMA/MACD/Donchian steps. Context metadata, higher-timeframe label, session/clock, news, manual prose, quotes and order-flow notes are excluded from the selectable sourced set.
- The trigger is checked separately and must be `met`. The score is the sum of enabled condition weights whose current status is `met`, on a 0–100 points scale. `gateMet` means score ≥ threshold, but strategy eligibility additionally requires approval, a met trigger, valid same-version candidate/bindings, point-in-time-safe fresh closed-bar evidence, no active pending condition, and a positive score from at least one met enabled condition.
- Waiting/failed native steps map to **not met**; unknown remains **pending**. A missing/stale/disconnected/future/incomplete active source blocks eligibility. The native source freshness allowance is two explicit analysis timeframes; the runtime also rejects rolled-over/stale decision bars, time-unit errors, post-decision snapshots, cross-analysis candidates, and strategy/version/side mismatches.
- The result is an immutable-by-value review snapshot: trigger, checklist with source/timestamps/reasons, deterministic score, threshold, gate status, `strategyEntryEligible`, blocked reasons, strategy/config versions, and approval metadata. `successProbability` is always `null`.

**Important distinction:** a passed gate means only paper-review eligibility within the app's contract, not an order/execution permission. A valid configured gate can still be not eligible because its current trigger/conditions are waiting or because data is missing/stale. Unit tests exercise synthetic contracts and malformed/stale/time-boundary cases; they are not provider or device proof.

## Quantitative workbench: common controls and output

From **Strategies**, each quantitative card has **Run** (pairs, momentum, market making, macro/trend, held-out classification). The sheet lets the owner pick family, search/tap catalog markets, remove selected chips, set timeframe and bar request count, optionally select **one** device CSV/JSON OHLC file (8 MiB max, strict OHLC parsing), edit family settings and assumptions, then tap **Run model**. It can display a model status/summary, metrics, up to 12 signals, a text summary of equity observations, family-specific paper-plan references, and expandable source/provenance, validation, data requirements and limitations. **Show details** exposes this review material; **Retry** retains inputs after an error. The screen says a run is not a broker/live order. No quant output records or paper order are created by the workbench calculation itself.

Visible defaults: selected market starts with the workspace market; timeframe starts at the workspace timeframe; requested **Bars** starts at 300 (allowed 60–1,800); lookback 60, entry z-score 2, exit z-score 0.5, holding bars 5, starting equity 100,000, fee 0 bps, slippage 0 bps, starting inventory 0, order size 0.01, max absolute inventory 0.1. Family-specific fields are pairs: lookback/entryZ/exitZ/holdingBars; making: inventory/orderSize/maxInventory; all other families: lookback/holdingBars. Shared assumptions additionally expose fee, slippage, and starting equity. Zero cost explicitly means that cost is excluded, not that the venue is free.

The workbench imports at most one file per sheet state; it tags the history as owner import, tied to the first selected symbol and timeframe. The pure models preserve provider/import provenance distinctly. Output **ready** means model calculation/data checks completed; **insufficient-data** means required usable sample/source/data are missing; **unavailable** means the model/input cannot be used under its contract. Neither status is a performance verdict. The detailed validation fields distinguish train/test, walk-forward, holdout, sample counts and reasons; a ready result can still say validation unconfirmed.

## Confirmed source defects

1. **Personal strategy creation and duplication bypass the documented 100-record cap.** `strategies.tsx:96–99` and `:271–274` enforce the limit for one/all added references, while **Duplicate as personal strategy** appends without checking at `:126–141` and **New personal strategy** appends without checking at `:175–191`. At/near the cap, these actions can exceed the UI's stated “100 strategy records including archives” capacity. Minimal fix: apply one shared capacity check before either append (and preserve the user's source record unchanged).
2. **Editing a factor with zero weight silently resets it to 10.** Factor weight is a valid 0–100 value in the personal factor control (`strategies.tsx:580–597`), but rebuilding edited factor lines uses `old?.factors[i]?.weight || 10` at `:165`, treating legitimate `0` as missing. Minimal fix: use nullish fallback (`old?.factors[i]?.weight ?? 10`).
