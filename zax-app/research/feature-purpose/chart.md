# Chart, timeframe bias & market context — feature guide

**Capability ID:** `chart`  
**Screen:** Chart (`app/(tabs)/index.tsx`)  
**Operating boundary:** owner-authorized, read-only market research plus explicitly initiated **paper** planning. The chart does not send brokerage orders. No source code, account database, or API state was changed or written during this audit.

## At a glance

This screen brings together a selected-market candlestick view, closed-bar timeframe classifications, and dated context/provenance. The app's seven chart timeframes are **1m, 5m, 15m, 1h, 4h, 1d, 1w**. Chart history and quote prices have distinct sources and freshness: a live quote/ticker does **not** make the underlying historical bars or analysis live. In Sample mode the bars are generated demonstrations and are labelled as such; they are not observations, backtest evidence, or proof of an edge.

Source references below are project-relative and use 1-based lines. Status means **implemented in inspected source**, not proven on a device: this read-only audit did not run a browser or device. The associated chart/bias/context tests use synthetic fixtures; they verify selected pure logic and bridge behavior, not a live feed, phone/browser rendering, or statistical performance.

## Features and how to use them

### 1. Selected market, feed status, quote and chart timeframe
- **Purpose:** Establish which instrument and bar interval the trader is viewing, and distinguish a current quote from historical chart data.
- **Location:** Chart market card and timeframe button rail, `app/(tabs)/index.tsx:798–895`.
- **Use:** Open Chart for the workspace's currently selected market; the inspected screen does not contain a market picker. Read the provider/status pill, quote source/age, and historical chart caption. Tap one of `1m`, `5m`, `15m`, `1h`, `4h`, `1d`, `1w` to change chart and setup timeframe. If the live quote is unavailable, use **Open context → Explicit Sample chart** only to explore the interface with clearly marked demo bars; switch it back off before asking for actual analysis or a paper proposal.
- **Output:** Provider symbol/name, quote (when available), change percentage (when supplied), source/time age, and historical bars/status. Coinbase can stream a current tick into the forming chart candle; feeds remain source-labelled. Source implementation requests up to 300 chart bars. FMP history requires a configured read-only data key and instrument entitlement; pending/unconnected feeds return unavailable rather than invented market bars. Private TradeLocker access is owner-gated and retains the provider's BID/ASK candle basis.
- **Useful next action:** Check whether the selected feed and its timestamps fit the decision; then inspect actual candles or compare the closed-bar timeframe-bias rows.
- **Status:** Market card, timeframe rail, historical candle query, and explicit sample toggle are present in source. Live service/device behavior is unverified here.
- **Limits / prerequisites:** A valid selected instrument and reachable, entitled historical feed are needed for real bars; quote availability is separate. Sample mode creates generated sine/cosine demonstration bars and disables automatic setup evidence, timeframe-bias fetch, and paper proposals. Weekly live data depends on declared source calendar/coverage; broker and non-crypto weekly aggregation are explicitly refused where session calendar is undeclared. Do not interpret a live quote pill as proof the history is current.

### 2. Candlestick canvas: inspect, navigate, details and renderer recovery
- **Purpose:** Inspect actual OHLC bars and navigate price history without confusing the chart with an execution surface.
- **Location:** `components/trading/candle-chart.tsx:23–77, 116–169, 170–378`; mounted at `app/(tabs)/index.tsx:897–967`.
- **Use:** Tap a candle/crosshair to inspect it. On the canvas, drag horizontally or pinch to navigate/zoom; scroll vertically outside it to move through the page. Use `−` (**Show more candles**), `+` (**Show fewer candles**) or **Latest** (reset). Tap **Details** for source label, inspected/latest bar date and exact OHLC, supplied price lines/zones, attached indicator names, and any forecast/replay provenance. If canvas startup/render fails, tap **Retry chart**; if still unavailable, tap **Use SVG fallback**, then **Retry canvas** to return to the canvas renderer. The fallback is explicitly labelled and is not Lightweight Charts.
- **Output:** Candlesticks, price scale/time ticks, actual inspected candle OHLC, and overlays supplied by the screen. The primary chart is TradingView Lightweight Charts inside an isolated local WebView/web document; attribution opens TradingView. The SVG fallback remains a display-only alternative.
- **Useful next action:** Verify the inspected candle timestamp/source and use the chart's details/levels to compare price location with the relevant closed-bar context.
- **Status:** Both render paths, inspection/navigation commands, details sheet, attribution and explicit retry/fallback are in source. Bridge/controller tests exercise mocked/synthetic payloads only; no real device renderer proof was obtained.
- **Limits / prerequisites:** Actual candle source data is required to see a real chart. No bars yields a no-source message rather than fabricated history. Forming/ticker-updated candles must not be treated as closed-bar evidence. Times are rendered in device time in the Lightweight canvas; session/strategy clocks are separately shown in the context strip. Fallback visuals are not equivalent to full canvas features (AI forecast explicitly requires the canvas renderer).

### 3. Chart overlays and named price annotations
- **Purpose:** Put price landmarks and selected rulebook zones in visual context, without treating every line as a signal.
- **Location:** **Chart tools & levels** disclosure and **Add named level** sheet, `app/(tabs)/index.tsx:1225–1269`; chart level rendering is in `components/trading/candle-chart.tsx` and the payload builder.
- **Use:** Scroll to **Chart tools & levels**, expand it, and toggle **Regular FVG + CE zones**, **Range quarters + OTE**, **Manual named levels**, or **Previous provider day PDH / PDL**. To annotate, tap **Add named level**, enter a name and positive price, then **Save manual level**. The modal initially suggests the current live quote when available. A manual level is attached to the active strategy and current market; strategy visibility controls whether it is included. Use **Details** on the chart to inspect supplied line prices.
- **Output:** Deterministic three-bar fair-value-gap zones/CE, range-ratio levels calculated from visible bars, enabled manual named lines, provider-day PDH/PDL when returned, and source-matched automatic strategy zones. FVG overlay rendering also depends on a visible strategy having an enabled FVG-related factor; chart code keeps automatic setup zones separate from manual/regular overlays.
- **Useful next action:** Compare a displayed level with the actual candle and source details; disable overlays that obscure price. Confirm that a provider-day level is available before relying on it.
- **Status:** Toggles and manual-level form are implemented in the screen source; actual line appearance depends on chart payload and data.
- **Limits / prerequisites:** No broker drawing tools, drag-to-create levels, orders, or strategy-independent manual-analysis claims are implied. Manual levels require a positive finite numeric value and active strategy. Previous-day levels require completed provider-day analysis; absent data is shown as unavailable. Sample-mode bars/derived overlays are demo geometry only.

### 4. Historical source scenario (replay) and direction-watch control
- **Purpose:** View an explicitly historical continuation/replay as context, not a forecast, and optionally create a local alert rule for a direction change.
- **Location:** **Historical scenario** disclosure, `app/(tabs)/index.tsx:1167–1224`; chart labels are handled in `components/trading/candle-chart.tsx`.
- **Use:** Expand **Historical scenario** and toggle **Historical source scenario**. If source history supports it, choose **Line**, **Ghost OHLC**, or **Both**. Tap **Notify me when scenario direction flips** to create/enable the local direction-watch rule. The screen tells you the watch must subsequently be saved in Alerts and a native-device/deployed scan activated; the first observation seeds its baseline.
- **Output:** A source-labelled historical replay; it may be strategy-matched or, when that is unavailable, explicitly labelled context replay. The chart prints **HISTORICAL REPLAY · NOT A FORECAST**. The alert action updates a local rule and displays the save/activation caveat; it is not a trade order.
- **Useful next action:** Inspect the replay source/basis and timestamps; keep it distinct from a forecast. For alerts, finish the separate save-and-activate steps in Alerts if desired.
- **Status:** Replay control/style and local direction-watch creation are in source. Runtime alert delivery and real replay availability were not exercised.
- **Limits / prerequisites:** Real completed history and an analysis/scenario are needed; Sample mode disables the direction-watch action. The watch action alone does not save cloud rules, run a scan, or submit an order. A replay is historical evidence, not predictive validation.

### 5. AI hypothetical forecast panel
- **Purpose:** Request a conditional, model-generated what-if path to discuss assumptions and invalidation—not to predict a price or produce a trading signal.
- **Location:** **AI forecast scenario**, mounted by `app/(tabs)/index.tsx:1153–1166`; controls in `components/trading/ai-forecast-panel.tsx:10–135`.
- **Use:** Expand the panel, optionally enter a scenario question (up to 800 characters), and tap **Generate AI scenario**. After a result, use **Show AI forecast** and `line` / `candles` / `both`, read thesis, assumptions, invalidation and generated/expiry/source details; use **Regenerate from current data** or **Remove forecast** as needed.
- **Output:** A blue hypothetical projection separate from actual bars and historical replay, with thesis, assumptions, invalidation, source/model, generated/expiry times, and source closed-bar anchor.
- **Useful next action:** Challenge each assumption/invalidation against actual source evidence; do not convert the projection into a paper entry by itself.
- **Status:** UI and mutation wiring are present. Forecast provider/model delivery was not called or verified during this read-only audit.
- **Limits / prerequisites:** Disabled in Sample mode; panel says actual connected market data is required. The chart canvas renderer is required to show the projection (SVG fallback warns that it cannot display it). The panel explicitly says there is no validated success probability/edge; projected volume is a display placeholder.

### 6. Closed-bar timeframe bias (seven-frame classifier)
- **Purpose:** Answer “do completed bars on this interval show a mechanically aligned uptrend/downtrend, or mixed/no usable evidence?” It is a quick directional context check, not a recommendation or eligibility check.
- **Location:** **COMPLETED-BAR BIAS** table in `components/trading/timeframe-bias-table.tsx:55–175`, inserted after chart evidence disclosures at `app/(tabs)/index.tsx:1149–1152`. Expand **Bias details & provenance** for the definition and per-frame source details.
- **Use:** Turn off Sample mode. Scroll to **COMPLETED-BAR BIAS**; wait for each frame, then tap **Refresh** or pull down inside the list. Read each row on its own (1m through 1w). Expand **Bias details & provenance** to check provider/source, as-of time, newest completed bar, eligible-bar count, EMA values and warnings. If rows say **Insufficient**, **Stale**, or **Unavailable**, do not read them as a direction; check feed/history/freshness or retry.
- **Actual pure math:** `lib/trading/timeframe-bias.ts:58–62, 64–80, 123–266` defines bullish only when latest completed close > EMA20 > EMA50 **and** EMA20 > its value five completed bars earlier; bearish is the exact inverse. Every other valid completed-bar configuration is **Mixed / neutral**. EMA20/EMA50 use the code's simple-average seed followed by the standard recursive EMA update. Each timeframe is calculated separately. Invalid bars and duplicate timestamps are excluded; forming/future bars are excluded; gaps are warned about and never filled. No bars are carried forward or invented.
- **Default data/parameters:** The screen requests exactly **1m, 5m, 15m, 1h, 4h, 1d, 1w** for the selected market. A row needs at least **55 eligible completed bars** to support EMA50 and the five-bar EMA20 comparison. Freshness limit is the larger of three timeframe bars or 15 minutes. One frame can fail without erasing other frame results. The query is owner-gated on the server (`server/trading/bias-router.ts:217–222`), fetches source candles only (not quotes), uses at most three concurrent fetch workers and a 25-second refresh budget. Coinbase crypto weekly uses up to 900 real daily bars aggregated into exact Monday–Monday weeks; other feeds depend on the server's declared timeframe support and source history.
- **Output/status meaning:** Bullish, Bearish, Mixed / neutral, Insufficient, Stale, or Unavailable; details expose the exact rule and provenance. **Insufficient** means no valid completed data, fewer than 55 completed bars, or incomplete EMA inputs, so no direction is assigned. **Stale** means the newest completed bar exceeds the freshness threshold. **Unavailable** means the frame fetch failed/timed out. Mixed/tied conditions are neutral, not a forced binary signal.
- **Useful next action:** Use rows to compare time-horizon alignment, then independently inspect the candle chart and timestamps. You can wait for adequate fresh source bars or treat conflicting frames as context to investigate—not as a trade instruction.
- **Status:** Pure classifier, owner-protected fetch route, and refresh/provenance UI are implemented. `tests/trading/timeframe-bias.test.ts` tests rising/falling/neutral/insufficient/stale paths and weekly aggregation with synthetic fixtures. These tests are not device/feed verification and say nothing about predictive edge.
- **Limits / exact prerequisites:** Owner access allowed by server policy, selected market accepted by feed, working API/provider access, and enough fresh, valid completed bars are required. Sample mode intentionally disables the fetch. Insufficient/no-signal is an honest “no classification” result, not a bearish/bullish absence, a strategy miss, or a failure of an unvalidated trading system. This operational classification has no reported outcome study, costs/slippage model, calibration, or out-of-sample test here; it establishes no edge. It only helps the trader compare source-labelled timeframe contexts; it does not create/queue multi-leg orders or place trades.

### 7. Pinned historical profile, previous provider day and clocks
- **Purpose:** Quickly answer “what broad profile did the setup analysis report?”, “where were the prior provider-day high/low?”, and “what are the relevant strategy/session clocks right now?”
- **Location:** Pinned **CLOSED BARS / PREVIOUS PROVIDER DAY** strip and expandable **Historical profile & clocks**, `components/trading/weekly-context.tsx:14–140`; supplied by the Chart screen at `app/(tabs)/index.tsx:709–716`.
- **Use:** Read the pinned bias and PDH/PDL summary. Expand **Historical profile & clocks** for profile basis/explanation, source/as-of record, completed provider-day timestamps, London/New York/Tokyo clocks, strategy timezone and device timezone. Use **Open context** in the screen header to switch between **New York (DST)** and **Fixed EST** if your intended strategy rules require it.
- **Output:** Profile bias (or Unknown), previous provider-day high/low (or unavailable), source and times, session window, and current region/device clocks. Clock refreshes every 15 seconds; profile/day values come from the setup analysis.
- **Useful next action:** Confirm source/time basis before interpreting a session boundary; compare displayed day levels with the chart only when present.
- **Status:** Strip and detail disclosure are in source. No provider day/profile data was fetched or checked on a device in this audit.
- **Limits / prerequisites:** Profile/day fields require setup analysis and eligible completed provider history. Missing profile displays Unknown and missing day levels display unavailable; no values are manufactured. Strategy timezone changes session-rule interpretation, not the provider candle timestamps. Device time is informational.

### 8. Economic calendar and COT records
- **Purpose:** Put scheduled macro releases and dated positioning records beside the chart as context for “what reported event or historical futures-positioning release might matter?”
- **Location:** Scroll to **Calendar & COT context**; expand it. It renders `MarketContextTable` in `components/trading/market-context-table.tsx:11–101`, with query wiring in `app/(tabs)/index.tsx:257, 1402–1431`.
- **Use:** Expand the disclosure; review each event name/date/country, actual/expected/prior fields when available, impact label and source. Then review report date, commercial long/short values, unit and source for each COT record. Read the summary and per-row caveats before using the data.
- **Output:** Up to 10 economic-event records and 6 COT records, with source strings and a partial/unavailable message when applicable. With no FMP key, the public fallback covers a finite US subset of BLS/BEA schedules, Fed FOMC meeting dates and one verified CME Bitcoin futures COT contract. Its schedule has no forecast/actual/prior surprises; event impact is a fixed StratDesk importance label. With FMP configured, server requests FMP economic-calendar/COT endpoints. Query results are cached server-side (calendar 5 minutes, COT 1 hour on FMP path; public adapter 5 minutes).
- **Useful next action:** Check event time-known/source and report date/vintage; consult the named underlying source for decisions that require current or instrument-specific coverage.
- **Status:** Read-only query, source-caveated table and official-source fallback exist in source. No live response or entitlement was verified in this audit.
- **Limits / prerequisites:** API/backend must be reachable; FMP path needs a configured read-only FMP key and endpoint entitlement. Public fallback may be partial. Calendar is not a complete global feed and may not map to the selected broker instrument. COT is dated weekly futures positioning—not spot ownership, all-market positioning, live flow, sentiment, or bias. The screen shows no fabricated record if lists are empty.

### 9. “Open context” settings sheet: sample, strategy clock and explicit cloud workspace actions
- **Purpose:** Make the chart's demo-data and strategy-clock assumptions explicit and allow deliberate workspace save/load.
- **Location:** Tap **Open context** in the Chart header; `app/(tabs)/index.tsx:718–733, 1438–1504`.
- **Use:** Tap the header icon labelled **Open context**. Toggle **Explicit Sample chart** only to explore generated demos; choose **New York (DST)** or **Fixed EST** for strategy clock basis. Tap **Save to cloud** or **Load cloud** deliberately if needed; read the returned status message. Close with the sheet close control.
- **Output:** Local chart mode/timezone change; cloud action status when requested. Save/load is explicit, not automatic. Sample mode visibly marks demo bars and blocks setup/bias/forecast/paper-proposal generation as described above.
- **Useful next action:** Turn Sample back off before interpreting market data; check access/feed status before using actual-data tools.
- **Status:** Controls are wired to workspace settings and explicit save/load callbacks; cloud success was not tested.
- **Limits / prerequisites:** Real source data for real analysis. Cloud operations require owner-authorized connectivity; do not infer success without the response message. This sheet is context/settings, not a data-provider connection wizard.

### 10. BUY / SELL: open a paper-plan proposal, not a brokerage order
- **Purpose:** If the trader chooses, turn chart context into a separately reviewed paper plan.
- **Location:** **BUY** / **SELL** buttons above the chart, `components/trading/candle-chart.tsx:131–152`; callbacks and proposal sheet are wired at `app/(tabs)/index.tsx:571–624, 956–958, 1565–1612`.
- **Use:** Turn Sample mode off, choose the intended market/timeframe and rulebooks, then tap **BUY** or **SELL**. Review the returned proposal in the paper-plan sheet, adjust displayed risk/management options as needed, and explicitly decide whether to create the paper record. Use Retry only when proposal retrieval failed. Closing the sheet cancels the pending UI request; it does not place anything.
- **Output:** An owner-authorized server paper proposal and—only after the sheet's explicit paper action—a server-confirmed paper-trade record that is shown on the chart with saved entry/working bracket. The code explicitly does not rebuild an order locally from a proposal.
- **Useful next action:** Verify source, entry/stop/target and risk in the sheet; create only a paper record if that is the intended test, otherwise close.
- **Status:** UI and paper proposal/order callbacks exist in source; no proposal or order was requested in this audit.
- **Limits / prerequisites:** Sample mode blocks proposals; actual provider/setup availability and owner-only paper API access are prerequisites. This is paper-only, not brokerage execution. No multi-leg/queued order functionality is established by this chart code.

## Confirmed source defect

- In Sample mode, the Chart screen disables the timeframe-bias query by passing `enabled={!workspace.settings.sampleMode}` (`app/(tabs)/index.tsx:1149–1152`). The table has no inactive/sample-mode explanation; while its query is disabled, it renders the same seven default “Checking…” rows because no result exists (`components/trading/timeframe-bias-table.tsx:61–73, 123–139`). Refresh is disabled, but the misleading indefinite loading-looking rows remain. **Minimal fix:** pass `disabled={workspace.settings.sampleMode}` and render an explicit “Unavailable in Sample mode—turn Sample off for source bars” state (or add an equivalent inactive state in the table) instead of `waitingRow` for all frames.

No other concrete defect was confirmed from the inspected source/tests. This is a source audit only; lack of device/browser/API verification is a caveat, not itself a confirmed product defect.
