# StratDesk Built-in AI Trading Coach (`coach`) — source-audit mini-guide

**Scope and evidence.** Read-only source review of `app/coach.tsx`, `components/trading/ai-coach.tsx`, `server/trading/coach-service.ts`, related coach/analytics/lesson code and tests, plus the quant family UI descriptions and pure calculation modules/tests for accurate boundaries. No app/browser/device run, live API call, database write, source/image access, brokerage action, or statistical test was performed. Unit tests use fixtures/mocks (quant fixtures explicitly synthetic); passing fixtures would verify algorithm cases, not the device, live provider/model, real data, or an edge. No simulated data here supports a performance claim.

## Entry and security boundary

- **Where:** protected route `/coach` (`app/coach.tsx:10-55`), titled **Trading Coach**, with Back and the private learning chat. `OwnerGate` wraps the screen; coach API endpoints are owner-protected (`server/trading/coach-router.ts:23-30`). `coach-service.ts:743-749` independently rejects identities outside the approved owner allowlist.
- **What it is:** educational, private, paper-only conversation. It has no order-entry or rule-edit action. It can suggest a review draft/checklist, but cannot place/submit/modify orders or claim guaranteed outcomes (`coach-service.ts:49-54,602-609`).
- **Data sent per question:** question, up to 14 prior turns, current workspace market/timeframe and active strategy ID, plus optional selected protected library record ID. Account grounding is loaded server-side: canonical workspace, up to 50 paper records, selected source metadata, recent screenshot-review metadata (if the optional repository method is present), computed learning facts, recent quant runs in current server memory, and optional read-only quote/closed-bar context. Market quote/bars are only requested when market (and timeframe for bars) is supplied; responses report exact source/timestamps/status and keep incomplete candles out (`coach-service.ts:794-1060,1162-1188`). It sends a source ID, never file bytes/image URI; source packet explicitly omits them (`coach-service.ts:416-439`).
- **Operational readiness:** status checks the live model catalog with an 8-second bound, caches it for five minutes and selects from catalog-listed models. The usual preference is `gpt-5-mini`, then `gpt-5`, then `gemini-3-flash-preview`; one catalog-listed alternate is tried only after an empty/truncated completion. Requests are bounded, rate-limited to 12 per 10 minutes, and no AI answer is fabricated on service failure (`coach-service.ts:38-47,663-769,710-735,1191-1247`). This source review did not verify that catalog/provider/network works on a device.

## Coach screen: controls, purpose and use

1. **Back** — leaves the coach route via router back (`app/coach.tsx:29-40`). Tap to return to the prior screen.
2. **Learn trading · process before profit** (toggle) — opens/closes six static educational lessons (`components/trading/trading-lessons.tsx:6-43,44-73`). Tap the toggle, then a lesson row to open its sheet; tap the sheet close control when done. Lessons are: **Risk before entry** (invalidation, planned dollar risk, sizing); **Trigger versus confluence** (separating a trigger from independent factors and checklist score from probability); **Price, costs and reward** (R:R, spread/fees/slippage, verified contract value and limits of venue depth); **Structure and uncertainty** (closed vs forming candles, testable chart concepts, missing evidence); **After a loss** (behavioral warning signs, pausing, optional—not mandatory—cooldown); **Review without fooling yourself** (process vs outcome and adequate samples). Each has a reflection question. These are static learning text, not a personalized signal or automated control.
   - Each lesson sheet has **Ask my AI coach**. Intended use: tap it to ask the coach to teach that lesson and work through its reflection. **Confirmed source defect:** it navigates with query key `prompt`, but `app/coach.tsx` only reads `initialQuestion` or `question`; the lesson text is therefore not passed as the initial draft. The coach route still opens, but the advertised prefilled ask is lost. Minimal fix: send `question` (or make the route explicitly accept `prompt`). See defect list below.
3. **Learning review · your actual paper records** (toggle) — tap to lazily fetch owner-only `coach.analytics`; tap again to hide (`components/trading/learning-dashboard.tsx:6-25`). It displays eligible closed paper outcomes, entry-feature and confluence-snapshot coverage; descriptive confluence-score buckets (count, descriptive wins, observed expectancy R where permitted); up to four human-only watch/review proposals and a scope note. The server analyzes canonical closed paper records, max 2,000 per bounded comparison; no legacy snapshot backfill (`server/trading/coach-analytics.ts:5-23`, `lib/trading/confluence-analytics.ts:6-8,703-823`).
   - **Interpretation/use:** compare coverage and coarse descriptive groups, then inspect record quality and decide what to document for a later human review. A group under 100 has rates/expectancy withheld or is insufficient; at/above 100 is still unconfirmed, not validated. It is paper ledger data, not live fills. No automatic strategy promotion/change occurs. If there is more than 2,000 history, scope says incomplete.
4. **Coach status and Retry context** — status line can say *Checking coach…*, *Coach ready*, *Coach unavailable*, *Context check unavailable*, or *Coach status unavailable* and may show the selected model. If the status query errors, tap **Retry context**. If service explicitly returns unavailable, asking is disabled; a status-check error is distinct from explicit unavailable and does not itself prove the ask service is down (`ai-coach.tsx:509-581`).
5. **Details / Hide details** — tap to expand/collapse server-reported context and capability labels (only when either list is nonempty). This is metadata, not an additional data-fetch or settings editor (`ai-coach.tsx:522-617`).
6. **Learning Prompts** — tap one to insert-and-send a prewritten question immediately, not just populate the composer (`ai-coach.tsx:69-90,214-227,619-638`). Four always shown: **Explain strategy** (active strategy in plain language and manual pre-paper checklist); **Break down confluence** (observations vs assumptions/unknowns); **Compare pairs** (avoid treating correlation as prediction); **Trading discipline** (process/risk limits/stop condition, no execution instruction). With a selected library source, a fifth **Ask about selected source** prompt is added. Prompts are disabled while request pending, before conversation storage is ready, or when status says unavailable. The page discloses that answers/citations do not validate setups.
7. **Question field and Send** — type a question and tap arrow. It accepts up to 1,600 characters, requires nonblank text and a verified owner session with local transcript loaded. A send includes the current workspace context for that request; it is not a live chart/order command. During a request the composer/prompt controls disable and show a pending response indicator. Failure/timeout leaves the exchange uncommitted and preserves a retryable question (`ai-coach.tsx:44-45,245-337,358-370,402-474`). The server can return educational prose, model name, context-status list, and authoritative source citations/timestamps. Answers render a safe limited Markdown subset; citation/source metadata appears under assistant messages (`ai-coach.tsx:668-763,811-927`).
8. **Retry question** — appears on an unsent-question card after a failed/timeout response; tap to resubmit the same text. It does not duplicate a completed exchange. Client timeout is 75 seconds; service completion timeout is 45 seconds (`ai-coach.tsx:44,283-298`; service `:40-42`).
9. **Clear** — tap **Clear** to cancel/invalidate an in-flight local request and remove the conversation for the current identity/scope/source from device AsyncStorage. It is disabled when there is nothing to clear. Storage is owner/scope/source-keyed and capped to a bounded conversation; it is local device state, not server history (`ai-coach.tsx:147-204,343-356`; `lib/trading/coach-ui-state.ts`, `tests/trading/coach-ui-state.test.ts:69-88`).
10. **Selected-library-source context** — the same chat component supports a compact library scope (`app/coach.tsx:18-23,49-53`; `ai-coach.tsx:62-67,214-227,476-507`). If opened with `scope=library` and a trimmed `sourceId` (max 100 chars), the page marks **LIBRARY CONTEXT**, changes the input hint, and includes a fifth source prompt. To use: open the protected library record's coach entry point, ask about that source, and inspect answer citations/context status. Server loads only the owner's source definition/metadata and explicitly excludes file bytes. It can report the source unavailable; a source citation is not verification of its claims. This audit did not access any actual source/image.

### What the coach can and cannot know

- A prompt may include up to 50 recent canonical paper records for response context, with calculated confluence/discipline facts. The separately expanded **Learning review** can page up to 2,000 closed records; that is not the same as the chat's 50-record cap.
- Current market data are optional and bounded: quote when a market is supplied; bars only when both market and timeframe are supplied, only completed bars, up to the last 30 closed bars included in grounding. The answer's context metadata is the place to check whether those reads actually succeeded, their source, stale/unavailable status and as-of. The page itself does not provide a user-editable market/timeframe/strategy control; these come from current workspace.
- If the user asks about dated calendar/COT topics, a bounded optional lookup may add dated events/COT context; it is not breaking news, and CME futures COT is not live spot/OTC positioning (`coach-service.ts:1073-1160`).
- The prompt tells the model to treat user question/history/source contents as untrusted data, not instructions, and to distinguish facts from unknowns. Answers remain AI-generated and educational; even a citation, returned context, or correct-sounding answer is not a setup validation or trade recommendation.
- Service errors (no live catalog/model, empty/truncated/unsafe response, timeout/rate limit, inaccessible account context) can yield a visible failure. Workspace/history/source/market fetch failures are recorded as unavailable context rather than silently converted to success (`coach-service.ts:805-937,968-1058`).

## Quant workbench family notes (pure-math audit only)

The five families are `pairs`, `momentum`, `making`, `macro`, `ml` (`components/trading/quant-workbench.tsx:27-70`; `lib/trading/quant-lab-types.ts:3-47`). This section describes the selected family calculations and requirements, **not a re-audit of shared workbench UI/API/data-provider diagnostics**. The UI's broad defaults are 300 requested bars, workspace timeframe/market initially selected, and family settings lookback 60, entry z 2, exit z 0.5, holding 5, fee/slippage 0 bps, starting equity 100,000, inventory 0, order size 0.01, max absolute inventory 0.1. Zero cost explicitly excludes a cost assumption; it is not an estimate of free trading. Every result has `ready`, `insufficient-data`, or `unavailable`; **ready means the calculation/data check completed only**. Inspect run details for actual source/provenance, bar counts, validation reasons, requirements and limits. No family submits an order. Use results as hypotheses/checklists for human review and, if desired, a carefully logged paper experiment—not as a live instruction or proven edge.

| Family and trader question | What the pure calculation does / actual output | Exact practical default requirements and what no signal/insufficient means | Validation boundary and what to do next |
|---|---|---|---|
| **Pairs / relative value** — “Do these two histories show a rolling relative spread worth investigating?” (`lib/trading/quant-pairs.ts`; fixture tests `tests/trading/quant-pairs.test.ts`) | Synchronous rolling OLS spread for exactly two selected series; hedge ratio, residual/z-score, hedge drift, lag-one autocorrelation, present-window Engle–Granger diagnostic, cost-assumption two-leg OOS replay/equity and—only if current z and cointegration gates pass—two signals and a two-leg paper-plan reference. Never fetches data or makes a single-leg substitute. | Exactly two distinct same-timeframe series with exact matching Unix-second candle timestamps, positive valid OHLC, closed bars only; need `max(100, 2 × lookback)` synchronized bars (default lookback 60 means **at least 120**); default 300 requested may still leave fewer after gaps/filtering. Pair pure runner requires lookback 20–500 (UI's generic input may accept less, but calculation rejects it); entry z > exit z ≥ 0; holding 1–500; positive starting equity/order size; nonnegative fees/slippage. **No signal** can mean present z has not crossed entry, latest intended position is flat, or the present cointegration test failed/flagged a possible break; it is not proof “no opportunity.” Insufficient means data not synchronized/long enough or rolling fit unusable. | A signal is still only a two-leg paper candidate. Replay is exploratory; validation remains unconfirmed and there is no untouched newest holdout. At least 100 resolved OOS pair outcomes are required even for a performance verdict; multiple-testing, funding/borrow, survival/delistings and executable simultaneous fills are absent. Inspect pair legs and assumptions together; do not decompose or submit them. The UI's “two-leg paper plan” does **not** mean two-leg paper execution is wired. |
| **Cross/time-series momentum** — “Which fixed-universe assets have positive/negative trailing momentum?” (`lib/trading/quant-momentum.ts`; `tests/trading/quant-momentum.test.ts`) | Ranks 2–8 supplied same-timeframe series at exact shared closed timestamps; chooses positive top and negative bottom quintiles, scales selected targets by inverse trailing volatility, applies supplied cost to turnover, and returns per-asset long/short/flat states, ranking/strength/reasons, exploratory equity/metrics and reference paper allocation. | Needs **2–8 distinct** sourced series, one common timeframe and more than lookback (default 60) valid, unique, closed bars per asset and more than 60 exact common timestamps; actual actionable completed interval also needs a later shared close. Default holding 5 bars, supplied fee/slippage 0. **No candidate/no completed interval** means no positive top/negative bottom momentum with usable nonzero volatility at a common time, or no later common close; insufficient means universe or history fails. No bar interpolation/forward-fill. | Always unconfirmed: no chronological walk-forward or untouched holdout, even if model status is ready; 100 actual nonoverlapping outcomes are a minimum review gate, not proof. No point-in-time membership, delistings, verified adjusted total returns, borrow, financing, market impact or fills. Review source labels, costs, ranks and weights; do not read equity or target allocations as forecasts. |
| **Market making** — “What passive quote levels fit this one current venue book, inventory cap and my stated costs?” (`lib/trading/quant-making.ts`; `tests/trading/quant-making.test.ts`) | Uses one supplied actual L2 snapshot (not candles) to compute top-five depth imbalance, midpoint/spread, a heuristic inventory-adjusted center, tick-rounded prices and lot-rounded quantities within stated inventory cap. May return passive **paper quote targets** or a flat/no-quote state. No equity, P&L, fill or queue simulation. | Exactly one actual product in UI; pure math requires a book identifying symbol/source/receipt time, positive tick and lot size, polled/streamed status, bid and ask arrays with at least one unique positive level on both sides, uncrossed best bid<ask, and book not future-dated. Defaults: inventory 0, order size .01, cap .1, fee/slippage 0. Fees/slippage must be supplied nonnegative. **No quote** when spread does not exceed supplied two-sided cost, usable levels fail, tick rounding fails, or no lot-sized capacity fits cap; missing book means insufficient data, not synthetic L2. | Validation is unconfirmed with zero actual resolved quote outcomes; performance requires at least 100 independent quote outcomes plus queue/fill/cancel/latency evidence, chronological walk-forward and untouched holdout. Snapshot is not queue position, fills, or costs. You can review quote targets manually only; no multi-quote queue/orders are wired. |
| **Systematic slow trend / “macro”** — “What do daily/weekly OHLC trend and inverse-volatility weights say?” (`lib/trading/quant-macro.ts`; `tests/trading/quant-macro.test.ts`) | Actually an OHLC-only multi-asset slow trend/volatility-scale calculation: delayed prior-close trend sign, inverse trailing-volatility weights, user bps costs on turnover, historical equity/metrics and next-bar-only direction targets. It is **not** a macro-release, rate-differential or vintage/revision model. | 2–8 distinct, same timeframe (1d or 1w), source-labelled valid positive OHLC, exact common closed timestamps, finite fetchedAt provenance, positive starting equity and nonnegative user costs (sum <10,000 bps). With default lookback 60, volatility lookback computes to 20, so at least **63 common bars** for two observations; requested 300 is the UI default. **Flat signal** indicates flat trend/zero or unavailable volatility; insufficient indicates too few common usable bars or invalid requirements. | Ready stays unconfirmed: 100 real independent OOS observations are a minimum review gate; this code sets no walk-forward split or untouched holdout. Macro data are explicitly unavailable; true release/vintage, forecast/revision timestamps, policy/rate/carry and matched total-return data are requirements, not connected inputs. Review labels/cost assumptions and do not treat next-bar target as an action. |
| **Held-out classification / ML** — “Can a small classifier distinguish costed historical direction in a time-ordered experiment?” (`lib/trading/quant-ml.ts`; `tests/trading/quant-ml.test.ts`) | Per-series bounded boosted decision stumps on lagged OHLC features; train-only scaling, purged chronological walk-forward checks and most-recent holdout. Returns walk-forward/holdout direction accuracy and counts, a latest direction signal with normalized ensemble margin, and optional holdout-only text equity. No probability calibration, data fetching, or order. | One or more series (up to 8 pure runner), supported timeframe, clean completed OHLC, default lookback 60 / holding 5 and nonnegative supplied costs. Each series needs at least **120 eligible costed outcomes**, plus ≥60 usable training rows and both outcome directions/discriminative model; in-cost-band samples are excluded. With 120 eligible outcomes holdout is only 24; the stated minimum 100 heldout outcomes needs more than ~500 eligible observations (depending on split). Up to 5,000 bars/asset are inspected. **No signal**/insufficient means not enough eligible outcomes or a model cannot be fit; not a negative trading view. | When output exists, validation remains unconfirmed; code requires ≥100 untouched holdout outcomes before an outcome gate could be assessed and always forbids edge/profit claims. Accuracy is experiment-specific; strength is a margin, not success probability. Inspect source, counts, cost and split; use as a research hypothesis only. |

**Quant math test evidence:** `tests/trading/quant-pairs.test.ts`, `quant-momentum.test.ts`, `quant-making.test.ts`, `quant-macro.test.ts`, and `quant-ml.test.ts` use synthetic algorithm fixtures and assert sample boundaries, time filtering, provenance or status behavior. They are not real-market/device/provider validation and do not establish an edge. `ready` is operational completion of a model/data check; `validation.status` remains unconfirmed, and validation reasons/sample counts must be read separately. Some families can show an operational signal even while validation is unconfirmed; others intentionally remain unconfirmed regardless of test fixture performance.

## Coach/quant tests and confirmed code issue

- Coach service tests: `tests/trading/coach.test.ts` cover auth denial, mocked model/market/repository, bounds, safety, fallbacks, source-byte exclusion and synthetic grounding. Coach state tests: `tests/trading/coach-ui-state.test.ts` cover bounded local conversation/history and identity/scope/source storage keys. These are unit/fixture coverage, not device proof.
- **Confirmed defect — lesson question not seeded into coach:** `components/trading/trading-lessons.tsx:99-104` pushes `/coach` with `params.prompt`; `app/coach.tsx:12-25` reads only `initialQuestion` or `question`. Therefore tapping **Ask my AI coach** does not prefill/send the intended lesson-specific reflection question. Minimal fix: rename `prompt` to `question` in the lesson route params, or add an explicit route alias. No other confirmed in-scope source defect was established in this read-only audit.
