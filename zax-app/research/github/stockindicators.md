# Stock Indicators repository: calculation and rule-pattern references

The supplied URL, [DaveSkender/Stock.Indicators](https://github.com/DaveSkender/Stock.Indicators), resolves to the maintained GitHub repository **`facioquo/stock-indicators-dotnet`**. Its README identifies the project as a C#/.NET technical-indicator library, says the NuGet package was formerly `Skender.Stock.Indicators`, and links to `FacioQuo.Stock.Indicators`. This verifies the repository identity but also means it is a reference—not a drop-in Expo/React Native dependency. [1]

The following are app-level, paper-analysis rule ideas independently paraphrased from documented indicator outputs. The library documents indicator calculations; it does **not** certify these combinations as profitable or prescribe the entry/exit rules below. All rules can be evaluated numerically after specifying parameters and bar semantics. “Manual” here refers only to choosing parameter values or deciding what to review—not to an indicator requiring a person to calculate it. No success rates are claimed.

## Candidate numerical patterns

- **Donchian range breakout / channel exit.** For a long-only paper signal, flag a close above the *previous bar's* N-bar upper channel; consider an exit when close falls below the previous bar's lower channel. Using the prior channel avoids accidentally including the evaluated bar in its own breakout threshold. The documented bands are the rolling highest High and lowest Low; centerline is their average. The docs say default `N=20`, require at least `N+1` bars, and return null for the first `N` results. This entry/exit interpretation is an app-authored rule, not a trading system defined by the library. **Status: numerical; parameter/close-vs-intrabar choice must be explicit.** [4]
- **SMA trend filter or moving-average cross.** A simple regime rule is “close above an N-period SMA” for an up-regime; a two-average variant flags a fast SMA crossing above a slower SMA and reverses on the opposite cross. An SMA is the average price over a lookback window; the docs' example consumes Close. The docs specify at least N bars and nulls for the first `N-1` results, but do not prescribe periods or crossover trade rules. **Status: numerical; fast/slow periods and cross/touch semantics are app choices.** [6]
- **MACD signal-line momentum cross.** Flag a bullish event when MACD crosses above its signal line and a bearish event when it crosses below; optionally require MACD to be above/below zero as an additional filter. The docs define MACD as fast EMA minus slow EMA, with the signal as a moving average of MACD and histogram as their gap. Documented defaults are 12/26/9. This event logic is an app-authored rule. **Status: numerical; zero-line filter and execution timing are optional app choices.** [7]
- **ATR trailing-stop review/exit overlay.** Apply a long-side review flag when a bar closes through the active lower (sell-stop) segment; use the indicator as a plotted paper stop or alert, not an order. The documented ATR stop has `N=21`, multiplier `3`, and close-based offset as defaults; `EndType.HighLow` is an alternate basis. Its first N outputs are null, and its initial segment before the first reversal plus first `N+100` periods are warned as unreliable. **Status: numerical output with substantial initialization caveat; choose lookback, multiplier, offset basis, and close-vs-intrabar rule.** [5]
- **Chandelier Exit trailing threshold.** For a paper long position, flag a review/exit when close crosses below the long Chandelier line; the documented indicator can also be configured for short positions. Defaults are 22 lookback periods, multiplier 3, long direction, with at least `N+1` bars needed and first N values null. The docs describe an ATR-offset exit line, not a complete entry strategy. **Status: numerical; position direction, parameters, and crossing semantics must be chosen.** [10]

These are useful candidates to compare in a paper-analysis view, not evidence of edge. For consistency, calculate signals from timestamped OHLCV bars with a fixed frequency and define whether a signal becomes visible at bar close or intrabar. Avoid look-ahead: compare against prior-bar thresholds where the current bar contributes to an indicator's range.

## Warm-up and implementation fit

The library's getting-started guide recommends **750 bars as a broad rule of thumb**, warns that minimum history may not provide converged values, and notes that many smoothed indicators need 250 or more preceding bars for better precision. It explicitly says market data must come from the user's own provider. [8] Use each indicator's per-page minimum and convergence notes rather than assuming one global warm-up: for example, MACD minimum is the greater of `2×(S+P)` and `S+P+100`, while its page recommends `S+P+250` history before the intended use date and warns of early precision deviations; ATR Stop requires `N+100` for warm-up/convergence and recommends `N+250` preceding periods for optimal precision. [5] [7] SMA and Donchian publish finite lookback null windows, while ATR Stop's initial trend estimate adds a separate reliability warning. [4] [5] [6]

For the Expo/RN paper app, the docs' **Batch (Series)** model is the closest conceptual match for recalculating from a fetched historical series; a local pure-function TypeScript implementation can expose aligned result arrays and null warm-up values. The source library itself is C#/.NET, so do not assume its package runs in React Native. Its docs recommend buffer lists for incremental bars and hubs for coordinated streaming; those styles are probably unnecessary for an owner-only, historical paper-analysis screen unless it later needs live incremental feeds. [1] [9]

Before adding a strategy, the app still needs decisions on: data provider and adjustment policy (splits/dividends), ticker/universe, bar interval and session/time zone, lookback periods, ATR multipliers and offset basis, long/short eligibility, close vs intrabar trigger semantics, treatment of gaps and missing bars, minimum-history gating, signal timestamp/availability, and whether the output is an annotation, alert, or simulated paper position. Any performance comparison also needs explicit fees, slippage, benchmark, sample window, and out-of-sample method; none are supplied by this repository's indicator definitions.
