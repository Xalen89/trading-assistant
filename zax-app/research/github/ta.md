# `bukosabino/ta`: indicator definitions, candidate paper-analysis patterns, and license

The requested repository is the public, non-fork repository **`bukosabino/ta`**, GitHub repository ID **116043206**, described as a Python technical-analysis library built on Pandas and NumPy. GitHub metadata lists it as MIT-licensed, unarchived, with `master` as its default branch. Its README presents 43 indicators and positions the package as a source of financial-series features; it does **not** prescribe a complete trading system or claim that indicator signals are profitable. [1] [2]

## Indicator reference and candidate rules

The repository's docs organize momentum, trend, and volatility indicators, document outputs and parameters, and show Bollinger Bands with a 20-period window and 2-standard-deviation multiplier as an example. The parameter values documented for individual functions are library defaults, not recommendations for any market or timeframe. [2] [3]

The following are **new, independently paraphrased candidate rules for paper analysis**, inspired by combinations of the documented indicators. They are not strategies supplied, tested, or endorsed by `ta`. Each can be represented as numeric conditions once its parameters and data conventions are fixed. No expected returns, win rates, or success claims are implied.

1. **Trend-filtered EMA pullback** — Treat price above a longer EMA, with that EMA rising, as a bullish context; flag a pullback toward a shorter EMA followed by a close back above it. Invert the comparisons for a bearish watch. **Status:** numerical candidate rule; the library supplies EMA calculations, not this entry/exit recipe. EMA is documented as an exponential moving average. [3]
2. **MACD signal-line momentum change** — Flag a potential bullish momentum change when MACD crosses above its signal line, and a bearish one on the reverse cross; optionally require the MACD line to be on the corresponding side of zero. **Status:** numerical candidate rule. Docs identify MACD as trend-following momentum and document MACD, signal, and histogram outputs, with class defaults 12/26/9. [3]
3. **Donchian range breakout with ADX context** — Flag a close beyond the prior rolling high/low boundary; optionally require ADX above a user-chosen strength threshold and use +DI versus -DI to label directional context. Ensure the breakout boundary excludes the signal bar if the intended condition is “break the previous range.” **Status:** numerical candidate rule. The library documents Donchian bands and ADX/+DI/-DI but does not define this combined rule. The documented windows default to 20 and 14, respectively. [3]
4. **Bollinger squeeze-to-expansion watch** — Identify a low-width Bollinger regime relative to a chosen historical width percentile, then flag a close beyond an upper/lower band as a volatility-expansion event. This is a breakout watch, not a directional forecast; optionally require separate trend confirmation. **Status:** numerical candidate rule. `ta` documents band width, high/low bands, and binary indicators for closes beyond bands; the example uses window 20 and deviation factor 2. The “squeeze” percentile and event sequence are proposed logic, not a package signal. [2] [3]
5. **RSI threshold reclaim, with regime gate** — In a separately designated range-bound regime, flag RSI crossing back above a configurable oversold threshold (or back below an overbought threshold) as a possible mean-reversion setup; suppress this interpretation in a strong directional regime unless deliberately testing countertrend signals. **Status:** numeric candidate rule with a manual regime-review option. The library documents RSI as a gain/loss momentum measure used to attempt to identify overbought/oversold states, but does not prescribe threshold values or a trading rule. [3]
6. **Manual price-structure confirmation** — After any numeric flag, ask a reviewer to mark whether the chart shows a clear swing-level break/reclaim and whether the signal is occurring into an obvious nearby level. **Status:** manual review; not calculated by `ta` and deliberately not a formal candlestick-pattern detector. Define a review checklist if results must be reproducible.

## Missing parameters before a paper test

The rule ideas above are not fully specified until the app's test record fixes: instrument/universe and session; bar interval and timezone; historical sample and data source; indicator lookbacks and any thresholds or percentiles; whether signals use completed closes or intrabar values; treatment of current-bar inclusion, warm-up rows, missing values and corporate actions; exact crossover/breakout and regime definitions; long-only versus short/flat behavior; entry timing and simulated fill assumptions; exits, invalidation/stops, position sizing and maximum exposure; fees, spread, slippage and liquidity assumptions; and how overlapping signals, gaps, and end-of-data positions are handled. Avoid using an indicator value calculated with information unavailable at the simulated decision time. Record the chosen rules and assumptions before comparing outcomes; treat results as exploratory rather than evidence of future performance.

For an Expo/React Native interface, the useful reference is the library's **feature/API organization and indicator naming**, not a drop-in package recommendation. Its README describes a Python/Pandas/NumPy workflow over timestamp and OHLCV series, and illustrates individual indicator outputs. That is not an Expo/RN integration guide. This research did not install or execute repository code, access brokerage services or a user session, or edit app code, configuration, or Git state. [2]
