# Systematic macro & trend following — audit (owner-only paper app)

**Finding:** This is a limited, long-only EMA-pullback reference model—not a systematic-macro system and not validated performance. `lib/trading/indicator-presets.ts:21-66` labels it reference-only: D/4H/W, EMA20/50 trend, first green EMA20 bounce, swing/EMA50 stop, visual 2×ATR guide; no automatic trail. `lib/trading/indicator-setups.ts:83-200` implements closed-bar alignment (close > EMA20 > EMA50; both rising over five bars), a six-bar touch/first-bounce check, stop reference and ATR guide. It can emit a “ready” candidate, not evidence of edge. `indicators.ts:31-65, 67-96` defines indicators and closed-bar values. Weekly/daily history is not a 5–10-year dataset: `server/trading/market.ts:21-31` returns at most 300 candles; 4H/weekly are aggregates, and broker weekly is unavailable absent a declared session calendar. Existing inputs are selected owner TradeLocker quotes/history and public Coinbase candles/ticker—not confirmed point-in-time macro or total-return data. `market.ts:33` says economic calendar/COT require FMP key; neither establishes 5–10-year point-in-time history.

**Confluence candidates (hypotheses only; not recommendations or validated):** (1) **Daily trend state:** at each completed D close, close > EMA20 > EMA50 and each EMA exceeds its value five completed D bars earlier (existing detector). (2) **Pullback event:** within six completed D bars, low touches EMA20; latest completed bar is the first green close above EMA20, with close > EMA50 (existing detector; treat as trigger, not independent confirmation). (3) **4H alignment:** same closed-bar EMA20/50 rising condition agrees with D direction; aggregate only complete UTC 4H bars. Likely correlated with (1); measure pairwise correlation and do not double-count if >0.9. (4) **Volatility context (new candidate, not implemented):** at each completed D close, ATR14/close is above the 75th percentile of the preceding 252 completed D ATR14/close observations (selected broker/Coinbase OHLC); compute threshold using prior bars only. Check correlation and freeze the rule before tests. No macro condition is source-supported.

**Validation/data gates:** No synthetic-fixture validation claimed. Setup engine explicitly withholds strategy-specific indicator outcomes (`setup-engine.ts:1226-31`). Python engine supports only MA-cross/FVG, up to two assets; it does rolling train→test selection but no untouched holdout, 100-trade gate, or multiple-testing correction (`python/research_engine.py:14-36,38-54,90-120`). Require ≥100 real, independent resolved setup outcomes; predeclared costs/rules, point-in-time inputs, closed-bar/no-lookahead execution; repeated walk-forward OOS; separate untouched holdout; multiplicity correction across all tried rules/weights; log condition states and test correlations. Polled broker candle volume is not verified exchange volume: `indicators.ts:167-173`; Coinbase volume is supplied asset volume, not cross-market consolidated volume.
