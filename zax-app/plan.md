# StratDesk — expanded native trading platform

## Product direction

Build a native iOS and Android trading platform using the existing Expo Router / React Native / TypeScript starter. WR1, imported from the shared 37-page `wr1 PDF.pdf`, is **one reference strategy, not the user's strategy and not the application's permanent rulebook**. Personal patterns, uploaded trading styles and future strategy profiles remain separate, editable and selectable. The active analysis strategy and the visibility of its chart overlays are independent controls; strategies can be compared, switched, hidden and reapplied without deleting them.

This revision replaces the earlier four-tab/foreground-alert plan. The requested target is now a full upload-and-learning platform with six main tabs, historical analysis, transparent future scenarios, source-linked pattern matches, style-adapted scoring and server-generated closed-app alerts. Dependency-dependent capabilities remain in scope, but cannot be represented as active before their prerequisites are connected and validated.

## Six main tabs and mobile navigation

1. **Trading Chart:** candlesticks, market/timeframe controls, weekly profile at the top, active strategy selector, independent layer visibility, confluence drawer and source-linked matches.
2. **Markets:** searchable watchlist with symbol/provider mapping, feed freshness and supported-market states; market-specific analysis and alert shortcuts, including XAUUSD.
3. **Trades:** Pending / Open / Closed sections, trade plans and pre-trade journal, complete history and closed-trade deep dives.
4. **Alerts:** smart alert rules, delivery/read states, market and strategy filters, clickable pattern alerts and Alert → Chart Jump.
5. **Strategies:** reference and personal strategy library, source/photo-based strategy search, strategy detail cards and Strategy → Chart Apply.
6. **My Library:** searchable Patterns + Styles collections, upload actions, named setups, label/correction tools and training history.

Use a compact native six-item thumb navigation bar with icons and short labels, plus full human-readable screen titles. Secondary flows use native sheets or full-screen editors. Settings, integrations and market-context details open from the relevant header, not an extra main tab.

## Uploads, pattern training and style learning

**Pattern Uploader / Learn From My Files:** select compatible files from the device Files picker or photo library. Initial explicitly supported formats: PNG, JPEG and WebP images; PDF strategy documents; UTF-8 TXT/Markdown and structured JSON rule files. Validate signature/MIME, size and parsing; display supported formats and reject unsupported or unreadable files clearly. Preserve the uploaded source, name, pattern label, market, timeframe, strategy association, notes and import timestamp. Never claim support for arbitrary file types.

**Trading Style Uploader / Style Library:** import a style document or image and extract candidate rules, entry model, invalidation/stop logic, target logic, allowed sessions, markets, risk constraints and score weights. The user reviews and edits extracted rules before those rules affect analysis and alerts. Keep each personal style separate from WR1 and other imported strategies.

**My Pattern Library:** one searchable collection of uploaded images and named setups. Search by name and tags such as FVG, IFVG CE, Order Block CE and RDRB CE. Add thumbnails, source/strategy cards, positive and negative examples, status, rule versions and optional user confirmations. Styles have their own subcollection rather than being confused with individual pattern examples.

**Custom Pattern Trainer:** upload examples, label the pattern, optionally annotate the region of interest, add correct/incorrect examples and inspect the extracted visual description. Version the pattern definition and retain accepted examples. Record a pattern's actual state as Uploaded, Analyzing, Needs review, Ready as reference, Evaluated or Failed. A reference-ready pattern is not automatically a validated detector.

**AI Learning Engine / continuous learning:** use the provided server-side multimodal AI service to interpret uploads into structured descriptions and rule proposals. Recognition retrieves the relevant labeled references and compares them with the current candle/chart context. Every accepted upload and match correction updates the user's reference set and pattern/rule version. This is a real reference-based learning loop—not a claim that the foundation model is fine-tuned after each upload. File analysis is asynchronous, bounded and retryable; preserve the input and expose errors rather than fabricating learned output.

**Style Adaptation Mode:** selecting a style changes the applicable rulebook, factor weights, filters, allowed entry models and alert predicates. Maintain an auditable explanation of which uploaded rule caused a score or suggestion. User edits override AI-extracted suggestions. No automatic changes to account risk limits or live trading behavior.

**Self-Evolving Engine:** persist match feedback and historical outcome evidence; propose versioned refinements to pattern definitions/weights. Candidate versions are evaluated against retained historical cases before promotion. Display what changed, why, evaluation data and rollback. Do not silently rewrite the active style or imply guaranteed improvement.

## Chart overlays and match confirmation

Render native candles and all overlay layers using the same `react-native-svg` coordinate model. Support inspection, timeframe selection, chart navigation and reset-to-latest. Strategy/color tags distinguish simultaneous layers.

**Live Pattern Overlay:** show recognized candidate regions and applicable CE/PD-array levels over actual feed bars when connected. Patterns inferred from images are suggestions; deterministic patterns such as regular three-candle FVG have explicit detectors. Label manual, AI-suggested and deterministic marks differently. Ambiguous PDF concepts require user-defined detection rules rather than invented formulas.

**Confluence Overlay:** include FVG/IFVG CE, named order blocks, Turtle Soup/liquidity sweep candidates, STDV extensions, swing/candle quarters, OTE, MOP and manually annotated RDRB/overlap/wick CE. Scope each level to its strategy, market, timeframe and source. Enable/disable each group and entire strategy independently, and limit stale marks so the chart is not flooded.

**Transparent Future Overlay:** toggle a low-opacity, dashed continuation of a selected historical analog or user-defined scenario beyond the latest candle. Distinguish actual bars from projected bars, use uncertainty/scenario labeling and show the historical source. It is a conditional scenario, not a known future path or guaranteed prediction.

**Pattern Match Confirmation:** inspect the suggested pattern, reference image and matching evidence side-by-side; Confirm / Reject / Correct label creates feedback. A confirmation concerns visual matching, not the success of a trade.

**Pattern Source & Strategy Card:** every candidate and alert links to the exact uploaded source/reference, author attribution, style/strategy version, supporting and missing factors, market/timeframe and detection timestamp. Photo-Based Strategy Search uses reference-image similarity/descriptions within the user's library; it is not a claim to identify every trading method from any photo.

## Confluence, probability and historical engines

**Confluence Counter / Breakdown:** weighted rule evaluation across Market Structure, Premium/Discount, Time & Price, Key Levels and PD Arrays. Show count, total possible weight, met/missing/unknown factors and provenance. Missing data is not automatically passed. Selecting a style changes the factor set and weights.

**Success Probability Score:** reserve a separate empirical/calibrated outcome estimate, not the confluence score renamed as a percentage. Define success relative to a specific entry, stop, target, horizon and costs. Derive historical outcomes from supported candle/trade data using chronological separation, no future leakage and explicit assumptions when a candle touches both stop and target. Display sample size, data range, market/timeframe, evaluation scope and uncertainty. Until sufficient labeled outcomes and an appropriate out-of-sample evaluation exist, show **Not calibrated / insufficient history** instead of an invented probability. Any historical hit rate must be labeled as such and is not a guarantee of future performance.

**Historical Pattern Engine:** import supported historical OHLC CSV/JSON, validate timestamps and bars, normalize comparable pattern windows, retrieve nearest historical references and track subsequent outcomes. Retain upload/reference versions so evaluation results remain reproducible.

**Cycle Analysis / Market Rhythm Tracker:** implement explainable candle-data statistics such as session behavior, realized volatility, return autocorrelation and recurring swing intervals, with lookback and insufficient-data states. Show analytical evidence rather than asserting that cycles dictate future prices.

**Quant + Hedge Fund Methods:** this screen groups explicitly defined research/risk methods: volatility/regime context, correlation/divergence, momentum/mean-reversion measures and scenario/risk sizing. It does not claim proprietary hedge-fund strategies, institutional performance or validated predictive power without evidence.

## Trade plans, journaling and deep dives

Pending trades hold a validated plan with market, side, entry, stop, targets, size/point value, applicable strategy/style and source match. Compute risk and reward-to-risk; reject invalid price geometry and zero-risk plans. This is analysis/journaling, not broker execution.

**Pre-Trade Thinking Journal:** detailed steps for higher-timeframe bias, liquidity objective, positioning/confluences, session/news context, entry trigger, invalidation, target rationale, risk, emotional state and final reasoning. Snapshot the strategy/rule version and factor evidence when saved.

Open/closed tracking records user-supplied fills and exits. **Full Trade History** filters and searches Pending / Open / Closed entries without rewriting old strategy snapshots. **Closed Trade Deep Dive** combines the plan, fills, outcome, actual R, confirmations, missed factors, rule adherence and review notes. AI review may summarize evidence and suggest questions; it must not invent fills or hindsight-only reasons that were absent from the record.

## Smart alerts that work with the app closed

Store market-specific pattern/level/score/style alert rules server-side, with threshold, timeframe, cooldown, session filters and enabled state. The deployed backend detects against an authorized feed even when the phone is not running. Use native remote push with a data payload referencing alert ID, symbol, timeframe, pattern/source and strategy version. A tap restores the relevant chart, highlights the match and opens its evidence card, including cold-start navigation.

Include alert history, deduplication/outbox state, push receipts, token invalidation and explicit feed/delivery freshness. Configure opt-in permissions and supported push builds. Display **Pending activation** when backend deployment, feed, native credentials or device token is missing. Do not silently downgrade this requirement to foreground-only alerts.

The platform-owned deployed-app scheduler supports minute-or-slower HTTP scans. Design for that cadence initially and label its latency. Sub-minute/tick-level detection would require a suitable persistent/event-stream architecture and is a distinct material decision. Do not run a detached sandbox process as an always-on production monitor.

Expo remote push requires a native development/release build, not Expo Go; Android needs FCM credentials, iOS needs APNs credentials, and the device must grant permission. Regular notification messages can be shown while the app is backgrounded or normally terminated. Android force-stop from system settings blocks delivery until reopening; OS/network policies mean delivery cannot be guaranteed. [1] [2]
